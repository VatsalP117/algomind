# Publishing Checklist

## Quick Start

```bash
cd algomind-extension
npm run build:release
```

This produces `releases/algomind-extension-vX.Y.Z.zip` — upload that zip to the Chrome Web Store.

---

## Pre-Upload Checklist

### 1. Version bump
- [ ] Update `"version"` in `manifest.json` (semver: `major.minor.patch`)
- [ ] Update `"version"` in `package.json` to match

### 2. Build verification
- [ ] `npm run typecheck` passes
- [ ] `npm run build:release` completes without errors
- [ ] Inspect `dist/manifest.json` — confirm **no `localhost`** in `host_permissions`

### 3. Assets
- [x] **Icons** — auto-generated in `public/icons/` (16, 48, 128)
- [ ] At least **1 screenshot** (1280x800 or 640x400)
- [ ] Optional: Small promo tile (440x280)
- [ ] Optional: Marquee promo tile (1400x560)

> Icons are generated by `scripts/generate-icons.py` and copied into the build automatically.
> To regenerate: `python3 scripts/generate-icons.py`

### 4. Store listing copy
- [ ] **Description** — clear, under 1,000 chars
- [ ] **Detailed description** — features, how it works
- [ ] **Privacy policy URL** — required even if you collect nothing
- [ ] **Support URL** (optional but recommended)
- [ ] **Category**: Productivity or Developer Tools

### 5. Privacy & permissions
- [ ] In the Web Store dashboard, declare:
  - **"Does your extension collect user data?"** → No (or be specific)
  - **"Does your extension use remote code?"** → No (MV3 forbids it)
- [ ] Justify each permission:
  - `storage` — save auth tokens & settings locally
  - `tabs` — read active tab URL to detect LeetCode problems
  - `host_permissions` — call Algomind API and read LeetCode pages

## Upload Steps

1. Go to [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole/)
2. Click **New Item** (or select existing item to update)
3. Upload `releases/algomind-extension-vX.Y.Z.zip`
4. Fill out the **Store Listing** tab
5. Fill out the **Privacy** tab
6. Fill out the **Pricing & Distribution** tab (Free / Paid, countries)
7. Click **Submit for Review**

---

## Post-Submit

- Review usually takes **a few hours to a few days**
- You'll get an email when approved or if rejected
- Once approved, the extension goes live automatically (or you can set a publish date)

---

## Updating an Existing Extension

1. Bump the version in `manifest.json`
2. Run `npm run build:release`
3. In the Developer Dashboard, open your existing item
4. Click **Upload new package**
5. Submit for review again

---

## Troubleshooting

| Issue | Fix |
|-------|-----|
| `zip` command not found | Install via `brew install zip` or use Finder → right-click → Compress |
| "Invalid manifest" error | Ensure `manifest.json` has no trailing commas and valid JSON |
| "Excessive permissions" rejection | Trim `permissions` and `host_permissions` to the minimum required |
| Missing icons rejection | Add 128x128 icon to manifest and zip |
| Reviewer asks for demo video | Record a 30-60s Loom showing the pairing + save flow |
